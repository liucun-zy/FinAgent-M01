# DeepSeek Harness host

This preset mounts the official DSH agent loop, session, model registry, native executor and action-graph plugin on a Cordis context. All DSH packages are pinned to 0.2.2-rc.1. The CLI accepts an initialized action-trace workspace and a task prompt. The catalog comes from the trusted Python backend for that workspace. It never loads tools requested by the model or instructions found in documents.

From the demo directory:

```sh
cd dsh_host
pnpm install --frozen-lockfile --ignore-scripts
cd ..
dsh_host/run --workspace /path/to/initialized/workspace --prompt-file /path/to/task.txt --config configs/efunds.eval_bounded_final.local.json
```

Use Node.js 24+ or set `DSH_NODE` to its absolute path. The launcher also recognizes the bundled Codex runtime. `DSH_PYTHON` overrides the demo virtual environment. The fixed Python model subprocess uses the existing ModelClient adapter, configuration, Efunds headers, secret loading, transport retry accounting and cost reservation. The DSH package version is included in each receipt. Each invocation creates a new session attached to the persisted ledger/DAG. The host keeps the selected workspace, prompt, model config and audit directory outside tool arguments generated by the model.

The model may propose several calls in one completion. Backend tools run in order and all business writes go through the Python handler. Only a successful immutable `tools/result` for `finish_stage` (maintenance) or `submit_answer` (QA), with the backend's committed flag, counts as submission. Once submitted, a synchronous DSH guard refuses subsequent calls. The normal preset has no generic shell, filesystem tool, network tool or subagent.

A run writes its DSH event stream, API call audit when applicable and final receipt to `.dsh/<session-id>` under the workspace by default. `--audit-dir DIR` selects a fresh directory. `--max-calls N` bounds DSH model steps for this invocation; the Python model client's config bounds total transport attempts and cost across all sessions in the project's default .dsh directory (maintenance, QA and retries). A lock protects the balance across processes. A custom --audit-dir outside .dsh has its own isolated budget. Usage reports the per-session spend, inherited project spend and original configured limits. The CLI emits one JSON receipt on stdout. A missing submission returns a nonzero status.

For offline replay pass `--script actions.json` instead of `--config`. The script replaces the source of model actions. The same DSH loop, native tool pipeline, guard, graph bridge and submission criterion are used. Each action is `{"name":"tool_name","arguments":{...}}`. A nested argument of the form `{"$ref":"0.route_id"}` reads a field of the first actual tool result, using zero-based call order. Offline replay measures prescribed actions; live QA uses the configured model to choose routes, evidence probes and submissions.

Official interfaces: [DSH tools](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/core/tools), [DSH agent loop](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/core/agent-loop).
